# Texturdle

A daily game: guess which video game a 3D model comes from. Five guesses, and each miss reveals more:

1. 10% of the model's textures
2. 30% of the textures
3. 50% of the textures
4. All of the textures
5. The textured 3D model

## Run it locally

Requires Node 22+ and Blender 4.x (Blender 5 removed the `.dae` importer).

```sh
npm install
npm run puzzles   # turn data/modelzipped/*.zip into puzzles
npm run dev       # http://localhost:5173
```

In dev mode a bar at the top lets you play any puzzle (`?practice=<id>`) and reset it.

## Deploying

The site is hosted on Cloudflare (Workers static assets, the successor to Pages) and deployed
from this machine, not from git:
built puzzles are large and are rebuilt from the zips, so `web/public/puzzles/` is gitignored.

```sh
npx wrangler login   # once per machine
npm run deploy       # build, then upload dist/ (settings in wrangler.jsonc)
```

Only new or changed files are uploaded, so deploying after a batch is quick. Cache
rules are in `web/public/_headers`.

Because the puzzles and the source zips live only on this machine (and the deployed
site), keep a backup of `data/modelzipped/`. `data/overrides.json` in git holds every
review decision, credit and fix, so the puzzles can be rebuilt from the zips at any time.

## Adding a batch of puzzles

1. Download zips from The Models Resource into `data/modelzipped/`, keeping their filenames.
   Each puzzle links back to its Models Resource page automatically: Windows records the
   page a file was downloaded from, and the pipeline saves it to `data/sources.json`. Download
   in the browser straight into this folder (copying zips via USB or cloud drives strips that
   record); for a zip without it, set `"sourceUrl"` in `data/overrides.json`.
2. Run `npm run puzzles -- --new` to build only the zips that haven't been built yet.
3. With `npm run dev` running, open **http://localhost:5173/review.html**. It lists every
   model with a preview render, its texture sheet, stats and warning flags (flagged first).
   - <kbd>A</kbd> approve, <kbd>R</kbd> reject, <kbd>T</kbd> rotate, <kbd>J</kbd>/<kbd>K</kbd> move,
     <kbd>P</kbd> play it in a new tab.
   - Rejecting removes the puzzle from the game immediately.
   - Rotating or un-rejecting needs a rebuild: `npm run puzzles -- <part of the name>`.
4. Decisions are saved in `data/overrides.json` (`"status": "approved"` or `"rejected"`).
   Commit that file; `data/review/` is regenerated by each build and is gitignored.
5. Run `npm run deploy` to publish. Only approved models are uploaded; anything built but
   not yet reviewed is held back (`pipeline/publish-filter.mjs`), so it is safe to deploy
   mid-batch.

## Adding a puzzle

1. Download a model zip from The Models Resource into `data/modelzipped/`. Keep the
   original filename (`Platform - Game - Category - Model.zip`): the game name comes from it.
2. Run `npm run puzzles` (or `npm run puzzles -- <part of the slug>` to rebuild one).
3. Check it in the dev bar.

If the pipeline picks the wrong model file or a texture spoils the answer, add an entry to
`data/overrides.json`:

```json
{
  "super-mario-sunshine-mario": {
    "model": "Mario/ma_mdl1.dae",
    "excludeTextures": ["sunglass"],
    "credit": "Ripper name",
    "sourceUrl": "https://models.spriters-resource.com/...",
    "accept": ["Other Game Title"]
  }
}
```

`accept` lists other game-list titles that also count as correct, for when a regional
release is listed as a separate game. Japanese and alternative names that Wikidata already
attaches to a game (Rockman, Bio Hazard, ロックマン) work without this.

Set `BLENDER=<path to blender.exe>` if Blender 4.3 isn't in the default install location.

## How it fits together

- `pipeline/build.mjs` unzips each model, runs `pipeline/blender_export.py` in headless
  Blender to export `model.glb` and list the textures the model uses, packs those textures into
  one sheet, and cuts the 10%, 30% and 50% hints from it with a seeded grid mask. Output goes to
  `web/public/puzzles/<id>/` plus `index.json`.
- `web/src/game.ts` holds the game rules, daily schedule (midnight UTC) and share text.
- `web/src/catalog.ts` is the list of games for the autocomplete. Puzzle answers are merged in
  automatically.
- `web/src/storage.ts` saves progress and stats in localStorage.
- `web/src/viewer.ts` is the Three.js model viewer, loaded only at the final stage.

This local version ships the answers in `index.json`, so anyone reading the network tab
can see them. Hiding them is a job for the deployed version.
